# SAYA.GGH

Website portofolio arsitektur dan desain untuk SAYA.GGH. Repository ini berisi aplikasi utama berbasis Next.js, dashboard CMS, integrasi Supabase, live chat, translasi bilingual, dan backend Express opsional.

## Ringkasan

- Aplikasi utama ada di folder `FrontEnd`.
- Data publik, admin CMS, auth, storage gambar, dan live chat memakai Supabase.
- Folder `BackEnd` berisi API Express/MongoDB terpisah yang masih tersedia untuk kebutuhan server kustom atau pengujian lama.
- Root `package.json` tidak memiliki script aplikasi. Jalankan command dari folder `FrontEnd` atau `BackEnd`.

## Teknologi

| Area | Stack |
| --- | --- |
| Frontend | Next.js 15 App Router, React 19, TypeScript |
| Styling | Tailwind CSS, Flowbite React, Framer Motion |
| Data | Supabase PostgreSQL, Supabase Auth, Supabase Storage |
| AI dan chat | Google Gemini API, local knowledge base, live chat admin |
| Backend opsional | Express 5, MongoDB/Mongoose, JWT, Multer |

## Environment Variables

Buat `FrontEnd/.env.local`:

```env
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your_supabase_anon_key
SUPABASE_SERVICE_ROLE_KEY=your_supabase_service_role_key
CHAT_SESSION_SECRET=replace_with_a_long_random_secret
GEMINI_API_KEY=your_gemini_api_key

# Opsional
CHAT_MAX_REQUESTS_PER_MINUTE=30
CHAT_MAX_MESSAGE_LENGTH=2000
CHAT_SESSION_CREATE_MAX_PER_MINUTE=20
```

Catatan keamanan:

- `SUPABASE_SERVICE_ROLE_KEY`, `CHAT_SESSION_SECRET`, dan `GEMINI_API_KEY` harus tetap server-side. Jangan menambahkan prefix `NEXT_PUBLIC_`.
- `NEXT_PUBLIC_SUPABASE_URL` dan `NEXT_PUBLIC_SUPABASE_ANON_KEY` memang aman dipakai client, selama RLS Supabase dikonfigurasi dengan benar.

Jika menjalankan `BackEnd`, buat `BackEnd/.env`:

```env
PORT=5000
MONGO_URI=mongodb://localhost:27017/sayaggh_db
JWT_SECRET=replace_with_a_long_random_secret
CORS_ORIGIN=http://localhost:3000

# Opsional
ADMIN_SETUP_KEY=replace_with_bootstrap_key
AUTH_LOGIN_MAX_ATTEMPTS=10
AUTH_REGISTER_MAX_ATTEMPTS=5
MAX_UPLOAD_BYTES=5242880
JSON_LIMIT=100kb
```

## Setup Supabase

Jalankan schema awal ini di Supabase SQL Editor untuk database baru:

```sql
create extension if not exists pgcrypto;

create table if not exists public.projects (
  id bigint generated by default as identity primary key,
  title text not null,
  location text,
  year text,
  status text default 'On Going',
  description text,
  tags text[] default '{}'::text[],
  image_url text,
  image_url_mobile text,
  gallery_urls text[] default '{}'::text[],
  created_at timestamp with time zone default now()
);

create table if not exists public.page_content (
  section text primary key,
  title text,
  subtitle text,
  body text,
  background_image text,
  image_url text,
  image_url_mobile text,
  updated_at timestamp with time zone default now()
);

create table if not exists public.team (
  id bigint generated by default as identity primary key,
  name text,
  role text,
  image_url text,
  image_url_mobile text,
  images jsonb,
  created_at timestamp with time zone default now()
);

create table if not exists public.news (
  id bigint generated by default as identity primary key,
  title text not null,
  date date default current_date,
  content text,
  image_url text,
  image_url_mobile text,
  gallery_urls text[] default '{}'::text[],
  images jsonb,
  created_at timestamp with time zone default now()
);

create table if not exists public.ai_knowledge (
  id bigint generated by default as identity primary key,
  topic text not null,
  content text not null,
  created_at timestamp with time zone default now()
);

create table if not exists public.chat_sessions (
  id uuid primary key default gen_random_uuid(),
  status text default 'ai',
  user_id uuid,
  created_at timestamp with time zone default now()
);

create table if not exists public.chat_messages (
  id bigint generated by default as identity primary key,
  session_id uuid references public.chat_sessions(id) on delete cascade,
  content text not null,
  created_at timestamp with time zone default now()
);
```

Lalu:

1. Buat bucket Supabase Storage bernama `images`.
2. Jadikan bucket `images` public untuk membaca gambar dari website.
3. Buat user admin di Supabase Auth.
4. Tandai user admin dengan metadata berikut di SQL Editor:

```sql
update auth.users
set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb) || '{"role":"admin"}'::jsonb
where email = 'admin@example.com';
```

5. Jalankan `FrontEnd/sql/harden-supabase-security.sql` setelah admin metadata siap.
6. Untuk database lama yang belum punya gallery berita, jalankan `FrontEnd/sql/add-news-gallery-urls.sql`.

Jika upload gambar dari dashboard gagal karena Storage RLS, tambahkan policy untuk bucket `images` setelah fungsi `public.is_admin()` dibuat:

```sql
drop policy if exists "Public can read images" on storage.objects;
drop policy if exists "Admins can upload images" on storage.objects;
drop policy if exists "Admins can update images" on storage.objects;
drop policy if exists "Admins can delete images" on storage.objects;

create policy "Public can read images"
on storage.objects
for select
to anon, authenticated
using (bucket_id = 'images');

create policy "Admins can upload images"
on storage.objects
for insert
to authenticated
with check (bucket_id = 'images' and public.is_admin());

create policy "Admins can update images"
on storage.objects
for update
to authenticated
using (bucket_id = 'images' and public.is_admin())
with check (bucket_id = 'images' and public.is_admin());

create policy "Admins can delete images"
on storage.objects
for delete
to authenticated
using (bucket_id = 'images' and public.is_admin());
```

## Route Frontend

| Halaman | Route |
| --- | --- |
| Home | `/` |
| About | `/about` |
| Project List | `/project` |
| Project Detail | `/project/[id]` |
| News List | `/news` |
| News Detail | `/news/[id]` |
| Admin redirect | `/admin` -> `/admin/login` |
| Admin Login | `/admin/login` |
| Admin Dashboard | `/admin/dashboard` |
| Admin Debug | `/admin/debug` hanya development |

API routes Next.js:

| API | Fungsi |
| --- | --- |
| `/api/admin/session` | Menyimpan dan menghapus cookie session admin |
| `/api/admin/chat/sessions` | Daftar session chat untuk admin |
| `/api/admin/chat/sessions/[id]` | Detail/update session chat |
| `/api/admin/chat/sessions/[id]/messages` | Pesan chat admin |
| `/api/chat` | Pesan live chat publik |
| `/api/chat/session` | Membuat, mengambil, dan menghapus session chat publik |
| `/api/translate` | Translasi bilingual dengan Gemini atau fallback Google Translate |

## Endpoint Backend Opsional

Jika `BackEnd` dijalankan di `http://localhost:5000`:

| Endpoint | Fungsi |
| --- | --- |
| `GET /` | Health check API |
| `POST /api/auth/login` | Login JWT |
| `POST /api/auth/register` | Register user, dilindungi setup key/admin |
| `GET /api/projects` | Daftar project |
| `GET /api/projects/:id` | Detail project |
| `POST /api/projects` | Tambah project, butuh admin |
| `DELETE /api/projects/:id` | Hapus project, butuh admin |
| `GET /api/content/:section` | Konten per section |
| `POST /api/content/:section` | Update konten, butuh admin |
| `GET /api/team` | Daftar tim |
| `POST /api/team` | Tambah tim, butuh admin |
| `DELETE /api/team/:id` | Hapus tim, butuh admin |

## Fitur Utama

- Halaman portfolio arsitektur dengan project, berita, about, dan team.
- Dashboard CMS untuk mengelola project, news, team, konten halaman, social link, dan slideshow home.
- Upload gambar desktop/mobile dan galeri, dengan konversi WebP di client.
- Website bilingual Indonesia/English dengan toggle bahasa.
- Live chat publik dengan mode AI atau admin support.
- AI Training Center untuk knowledge base chat.
- Middleware admin berbasis cookie Supabase session.

## Deploy

Deploy frontend dari folder `FrontEnd` ke Vercel atau platform Next.js lain. Pastikan environment variable production sama dengan daftar `FrontEnd/.env.local`, terutama:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `CHAT_SESSION_SECRET`
- `GEMINI_API_KEY`

Jika domain production berbeda, update allowed domain di Supabase Auth dan konfigurasi CORS/backend bila `BackEnd` tetap dipakai.
